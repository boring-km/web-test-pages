시각 디자인

시각적 완성도디자인 장점

음식 이미지와 캐릭터는 서비스의 인상을 만든다.

굵은 한글 타이포그래피, 코발트 색상, 입체적인 구름 캐릭터의 조합은 시각적 개성이 있다. 보통의 검색 목록 화면보다 브랜드 표현이 뚜렷하다.

첫 화면의 우선순위약점

브랜드 소개가 강하고, 바로 할 일은 뒤로 밀린다.

모바일 홈은 큰 배너와 재생 도구를 먼저 보여준다. 예쁜 첫인상에 비해 식당 선택·저장 목록으로 바로 들어가는 집중도는 낮다.

02

화면을 이해하고 조작하는 경험

용어·글자·정보 밀도

메뉴 이름과 일관성혼합

브랜드 언어는 친근하지만 기능을 바로 읽기는 어렵다.

‘맛볼·맛봄·볾이·말해볾’은 기억에 남지만 처음에는 뜻을 배워야 한다. 홈의 입체 그림과 지도의 선 아이콘도 시각적 밀도가 다르다.

글자와 정보 밀도약점

큰 장식에 비해 설명은 작고, 지도 도구는 많다.

모바일 홈의 바로가기 이름은 13px, 저장·기록 설명은 12px, 이미지 고지는 11px였다. 의미를 설명하는 글보다 장식이 더 강하게 보인다.

03

기술과 웹뷰 제약

기본 품질과 실제 제약을 구분한 평가

기술 기본기기본 수준

뒤로가기·키보드 대응은 기본 요건을 갖춘 것이다.

이력 복원·키보드 가림 대응·사진 축소는 일반적인 모바일 구현이다. 코드가 있다는 사실만으로 기술적 우수성이나 특별한 강점으로 평가할 수 없다.

웹·앱 구조와 심사제한적

공통 개발은 편리하지만, 설치의 추가 효용은 제한적이다.

화면을 공유하는 것은 유지·변경 측면의 이점이다. 속도·안정성·UX의 우위를 뜻하지 않으며, 웹뷰라는 이유만으로 심사 탈락이 결정되는 것도 아니다.

인증·공유·사진제약

시스템 연결은 표준적이고, 콘텐츠별 제한은 남는다.

시스템 인증 자체는 적절한 통상 방식이다. 공유·사진은 형식·용량에 따라 가능한 동작이 달라 같은 작업을 일관되게 처리하는 범위에는 경계가 있다.

작업 복구약점

웹 프로세스 종료 뒤 미저장 작업의 연속성은 약하다.

뒤로가기 이력과 이탈 확인은 있지만 종료 후에는 새 웹뷰로 시작한다. 저장된 자료와 별개로 작성 중 글·사진 선택·상세 문맥을 이어가는 범위가 좁다.

스크린샷은 평가 대상을 보여주는 자료다. 숫자와 테두리는 평가 영역을 표시한 것이며 원본 화면에는 없다. 소개·상품 화면과 디자인 미리보기를 구분했고, 사업성 판단에는 기존 외부 자료를 사용했다.

화면 평가는 운영 중인 소개·로그인 페이지와 공개 홈·지도 미리보기를 구분했다. 미리보기 비교 도구와 브라우저 확장 버튼은 제품 평가에서 제외했다. 개인 계정 내부 화면·실기기 네이티브 앱 전체를 직접 사용한 평가는 아니다.

REFERENCE · T8

앱을 설치하는 추가 가치와 웹뷰 평가

이 항목의 평가공통 개발의 이점은 있으나 기술적 우위로 볼 근거는 없다.

이렇게 평가한 이유

웹·앱 공통 UI는 변경을 공유하기 쉬운 구조다. 이는 개발 방식의 이점이며 속도·안정성·사용성의 우월함을 입증하지 않는다. 사용자 입장에서는 주요 UI가 웹과 겹치고, 오프라인 기록·푸시 등 설치 전용 효용의 범위는 제한된다. 네이티브 화면 비율만으로 심사 합격 여부를 판단할 수는 없다.

확인한 구현·자료

iOS는 운영 URL의 웹을 표시하고 위치·시스템 인증·공유·사진 저장·다운로드를 브리지로 연결한다. 표시 방향은 세로, 색상 모드는 light다. RELEASE는 APNs 푸시와 오프라인 개인 기록을 포함하지 않는다고 명시한다.

판단을 도출한 과정

공통 웹을 사용하므로 웹과 앱을 각각 구현하는 부담을 줄이는 개발 구조의 이점이 있다. 기기 연결도 존재하므로 단순 링크 모음과 같다고 평가할 수 없다. 반면 사용자의 주요 화면과 작업은 모바일 웹과 겹치고 오프라인 개인 기록·푸시 같은 앱 전용 경험의 범위는 제한된다. 그래서 앱 설치의 추가 효용이 현재 구성에서 크지 않다는 평가다.

평가가 적용되는 범위

Apple 4.2는 네이티브 화면 비율을 제시하지 않고 사이트 포장 이상의 유용성을 본다. 웹뷰라서 자동 탈락하거나 네이티브 기능 몇 개가 있으면 자동 통과한다는 결론은 모두 아니다. 이 보고서는 코드의 앱 고유 효용을 평가하며 심사 결과를 예측하지 않는다.

기본 화면과 뒤로가기

이 항목의 평가뒤로가기·이력 복원은 기본 품질에 해당한다.

이렇게 평가한 이유

화면과 모달을 되돌리고 스크롤을 복원하는 처리가 있다는 사실은 확인된다. 그러나 사용자가 예상하는 기본 이동 동작이므로, 구현의 존재만으로 기술적 강점이나 경쟁 서비스보다 나은 경험으로 평가하지 않는다.

확인한 구현·자료

하단 메뉴는 홈·동네지도·메뉴뽑기·약속·볾이로 구성된다. 화면 전환은 공통 Explorer 상태와 브라우저 history를 사용한다. iOS는 수평 스와이프에 의한 뒤로·앞으로 이동을 활성화한다.

이 항목의 평가키보드·안전 영역 대응은 기본 품질에 해당한다.

이렇게 평가한 이유

입력 중 메뉴를 숨기고 보이는 영역에 창을 맞추는 것은 모바일 화면의 기본 대응이다. 관련 처리가 빠져 있지 않다는 의미이며 특별한 기술력의 증거는 아니다. 모든 기기에서 입력 경험이 좋다는 측정도 아니다.

확인한 구현·자료

입력란에 초점이 있고 visualViewport 높이가 innerHeight보다 150px 넘게 작으면 하단 메뉴를 숨긴다. viewportFit 다이얼로그는 보이는 영역의 크기·위치를 따라간다. 리뷰 입력 글자는 16px, 입력란 높이는 최소 48px로 지정돼 있다.

판단을 도출한 과정

키보드 때문에 실제 보이는 영역이 줄어드는 상황을 웹에서 계산한다. 따라서 키보드가 항상 버튼을 덮는다고 설명하는 것은 맞지 않는다. 작성 중 이탈에는 beforeunload와 화면 이력 차단 처리가 있고, 웹 프로세스 종료 시에는 오류 화면을 표시한다. 재시도 함수는 reloadID를 바꿔 새 웹뷰를 만들며 시작 주소는 홈이다.

평가가 적용되는 범위

이탈 확인은 글을 자동 저장하는 기능과 다르다. 여기서 미저장 입력은 현재 편집 중인 웹 상태를 뜻하며, 서버에 저장된 일기·리뷰가 사라진다는 뜻은 아니다. 프로세스 종료가 얼마나 자주 발생하는지는 이 코드로 알 수 없다.

이렇게 평가한 이유

인증 창과 외부 링크

이 항목의 평가시스템 인증은 표준 방식이며 외부 이동에는 경험의 경계가 있다.

이렇게 평가한 이유

시스템 인증창은 통상적인 인증 수단이고, 임시 세션은 개인정보 보호를 위한 선택일 수 있다. 이를 사용했다는 사실 자체를 UX 결함으로 보지 않는다. 다만 웹뷰와 외부 앱을 오갈 때 원래 화면과 작업으로 돌아오는 경험은 분리된다. 실제 로그인 실패를 확인했다는 뜻은 아니다.

확인한 구현·자료

로그인은 ASWebAuthenticationSession에서 진행하고 일회 코드·PKCE 교환으로 웹뷰 세션을 연결한다. 해당 인증 세션은 prefersEphemeralWebBrowserSession=true로 설정된다. 외부 HTTPS·전화·메일·지도 링크는 UIApplication.shared.open으로 넘긴다.

판단을 도출한 과정

임시 인증 세션은 평소 브라우저의 쿠키·탐색 데이터를 공유하지 않는 세션을 요청하는 설정이다. 평소 브라우저에서 로그인한 상태가 앱 인증창에 그대로 이어진다고 전제할 수 없다. 이는 맛볾 계정의 자동로그인 쿠키와는 별개다. target=_blank인 내부 링크는 별도 앱 탭을 만들지 않고 기존 웹뷰에 로드된다.

평가가 적용되는 범위

인증 세션 분리는 로그인 실패를 뜻하지 않는다. 외부 앱 실행 실패 시 안내창을 표시하며 해당 앱으로 화면을 넘기지 못한다. 현재 구조는 앱 자체에 범용 브라우저 탭을 제공하지 않는다.

이렇게 평가한 이유

공유창을 여는 것은 기본 연결 기능이다. 사용자 경험의 평가 지점은 파일 배열·URL·용량 조건 때문에 같은 공유 동작으로 전달 가능한 내용이 달라진다는 데 있다. 운영 서비스의 공유가 전반적으로 실패한다는 뜻은 아니다.

사진 선택·표시·알림의 범위

이 항목의 평가사진 축소는 일반적인 처리이며 입력 형식의 제약은 남는다.

이렇게 평가한 이유

웹에서 사진 크기를 줄이고 JPEG로 변환하는 것은 일반적인 업로드 처리다. 차별적인 기술 강점으로 볼 근거는 없다. HEIC가 변환되지 않고 전달되는 경우의 거절, 장수·용량·해상도 조건이 사용자에게 보이는 입력 범위의 제약이다.

확인한 구현·자료

리뷰 사진은 웹 파일 입력으로 촬영·앨범 선택하며 JPG·PNG·WebP, 장당 입력 20MB 이하·최대 5장으로 제한한다. 긴 변 1600px 이하의 JPEG로 변환한다. HEIC 형식이 그대로 전달되면 입력 단계에서 거절한다. iOS 방향은 세로, 색상 모드는 light로 지정된다.

판단을 도출한 과정

사진 선택은 별도 Swift 사진 편집 화면이 아니라 웹 입력과 브라우저 이미지·canvas 처리다. 시스템 선택기가 JPEG로 변환해 전달하는 경우와 HEIC 파일이 그대로 전달되는 경우는 구분된다. 진동 함수는 navigator.vibrate만 사용하고 현재 브리지에 네이티브 햅틱 항목은 없다. 초대·친구 소식은 앱 내 알림이며, iOS 소스에는 APNs 등록·수신 경로가 포함되지 않는다.

평가가 적용되는 범위

HEIC를 촬영한 모든 사진이 실패한다는 의미가 아니다. 형식 제한은 웹에 전달된 File.type 기준이다. APNs 관련 설명은 제공된 iOS 소스 범위에 한정된다. 가로모드·다크모드 고정은 파일의 명시적 설정이다.

웹 상태 보관과 중단 복구

이 항목의 평가미저장 작업의 중단 복구 범위는 좁다.

이렇게 평가한 이유

웹 이력 복원과 작성 이탈 확인은 기본 안전장치다. 그와 별개로 웹 콘텐츠 프로세스가 끝나면 새 웹뷰에서 시작하므로 미저장 입력·선택 문맥을 이어가는 범위는 좁다고 평가한다. 저장한 자료가 사라지거나 앱이 자주 종료된다는 판단은 아니다.

확인한 구현·자료

탐색의 상세 상태는 JavaScript 메모리 Map에 보관되고 브라우저 history에는 세션·단계 표식만 기록된다. 일기·리뷰 작성에는 이탈 확인이 있다. 웹 콘텐츠 프로세스 종료 후 오류 화면을 표시하며 재시도는 새 웹뷰를 홈 URL로 연다.

판단을 도출한 과정

같은 문서 안의 뒤로가기는 상태 복원을 제공하지만 프로세스가 사라지면 그 메모리도 이어지지 않는다. 저장된 서버 자료는 다시 읽을 수 있어도 미저장 입력·사진 선택·상세 문맥을 그대로 돌려주는 기능과는 다르다. 따라서 평상시 탐색 이력은 다루지만 작업 중단 이후의 연속성은 상대적으로 약하다는 평가다.

평가가 적용되는 범위

이 평가는 종료 후 복구 경로에 한정한다. 앱이 자주 종료되거나 운영 서비스가 불안정하다고 판단한 것은 아니다. 이미 서버에 저장한 기록이 삭제된다는 뜻도 아니다.
